What is intentionally missing
  - No points, XP, levels, or percentile anywhere.
  - No five-day pill progress row.
  - No post-completion Home card and no bottom sheet.
  - No confetti and no green check.
  - No library picker on the camera screen, at all, ever — camera-only is a
    verification gate and an affordance that suggests otherwise breaks it.

The timer runs on the wall clock
  started_at + required duration is the whole model. The remainder is always
  derived, never decremented. Locking the phone, backgrounding, a call or the
  app being killed changes nothing, and hard mode does not exist on this
  surface — it is cut, along with its copy and its blocked state. While a timer
  runs, its real home is the lock-screen Live Activity
  (TimerLiveActivity.jsx); when it elapses, the completion notification fires
  wherever the user is ("10:00 done" / "Come back to post proof."). Reopening
  the app mid-run must restore the true remaining time, and reopening after it
  elapsed must go straight to Verifying.

Three rules that are not style preferences
  1. Never render the confirmation before the server responds. Verifying exists
     for exactly this reason.
  2. Orange is the verified colour on this surface. A self-reported completion
     gets the ink treatment. If you are unsure which a type is, read the
     "verified" column in taskTypes.js — it is written as user-facing copy on
     purpose.
  3. Every stat on the confirmation has a named query in README §5.2. If a
     number has no query, it does not go on the screen.

Sixteen open questions are at the end of the README; 5, 6 and 15 are now
resolved by the wall-clock timer decision. Numbers 1, 2 and 4 block
implementation; the rest can ship with the current behaviour and be revisited.
