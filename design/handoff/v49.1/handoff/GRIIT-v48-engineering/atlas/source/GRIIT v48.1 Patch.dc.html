Keyboard rules (all text entry)
Visible
The focused field and its last typed line stay at least 12pt above the keyboard. The screen scrolls the field into view on focus.
Primary action
The screen’s one button docks 8pt above the keyboard and stays tappable while typing.
Number pad
Every number pad gets a Done bar (input accessory). Done closes the pad; it never saves.
Counts
Live counts (words, characters, n of N) sit between the field and the docked button.
Sheets
A sheet shrinks to the keyboard top; its composer docks on the keyboard.
Dismiss
Drag down or tap outside a field. Typed text is kept.
Build
KeyboardAvoidingView behavior “padding” on iOS, keyboardShouldPersistTaps “handled”, InputAccessoryView for the number-pad Done bar.

Patch 4 · Which screen appears
Toast, Secured or FinishMoment
One rule decides the screen after every save. Within 3 seconds: the right moment, with the real numbers.
The rule · which screen appears after a save
After every save the client reads three facts from the completion response, then routes once. One screen per save, never two.
1
challenge_finished
This save secured the last day of an enrollment (day_index = duration_days and the day is secured).
FinishMoment
818
2
day_secured_now
secured_today flipped from false to true with this save.
Secured
817
3
otherwise
Any other task done.
Toast on Home
814
Checked in that order. A counter reaching its target only completes the task: it lands on 3, or 2 if it was the last task of the day, never 1 (frames 819, 820).
If the final day also secures other challenges, FinishMoment shows once; “See the record”, then Home shows the day secured. No second Secured screen.
FinishMoment and its card read enrollment.secured_days and enrollment.longest_streak from the server (frame 821). Held days hold the streak but don’t add to it.
